# GameForge 试玩与持续改进

本次把单次代码生成升级为带版本、证据和预算的改进闭环。现阶段自动改进面向独立 HTML / Canvas 横版游戏；文字冒险继续支持生成、编辑、分幕校验与导出。模型偏好只能说明代理评价，不能据此声称真人觉得好玩。

## 使用

1. 在 `.env.local` 配置 Qwen / DeepSeek 或兼容的 Gemini 生成凭据，参照 `.env.example`。不要使用 NEXT_PUBLIC_ 保存密钥。
2. `pnpm install --frozen-lockfile`，`pnpm dev`。默认只监听 127.0.0.1。选择已配置模型，分步或一键生成游戏。
3. 生成横版游戏后，在“试玩与持续改进”填写目标、玩家和约束。默认 3 轮、每版 3 局、30 次模型调用、30 分钟；连续两轮无改进提前终止。自动改进只复用冻结素材。
4. 在非 root Linux / WSL 用户下配置 Docker 权限、Python venv，执行 `python scripts/setup_worker.py`。Windows 在 `.env.local` 设置发行版、用户和 venv Python 的 Linux 路径。运行容器前不会自动拉镜像或降级为宿主运行。
5. 任务保存于 `<GAMEFORGE_DATA_DIR>/<gameId>/runs/<runId>`。关闭网页不停止独立 worker。界面支持停止、检查点恢复、证据、双版本试玩、离线导出与版本绑定反馈。
6. 可选择“仅试玩验证”，不派发设计或修改调用。历史任务下拉框可查看此前任务及证据。
7. 系统保留经过验证的最佳版本；在界面试玩后点“选用此版本”。选用检查当前版本，期间发生编辑会报冲突，任务不会覆盖新编辑。

## 执行边界与状态

- `src/lib/generation.ts`：一键与分步共享各阶段实现，素材逐张检查点保存。图片已完成且未强制重生成时复用。新 HTML 先检查 JavaScript 语法，失败最多修复两次，不执行模型代码做语法检查。失败保存已有阶段，重试继续。兼容模型流断开会中止后续调用；已发出的远程请求是否计费由供应商决定。
- `src/lib/versions.ts`：冻结记录、文本游戏渲染入口与素材，以 SHA-256 内容标识版本，检查源和素材完整性。修改前自动快照，回退恢复完整内容字段。预览、测试、ZIP 使用同一 HTML 和冻结素材，ZIP 附版本清单，不替换成示例游戏。
- `src/lib/improvement.ts`：创建任务、幂等 requestId、状态查询、停止恢复、导入候选版本。未测试/被拒绝候选可查看但明确标记 rejected。当前版本由用户显式选择。
- `worker/runner.py`：独立 Linux 控制器，调用真实模型设计/修改、实际按键试玩、A/B 与 B/A 盲评。通过匹配且仅匹配一次的少量文本替换构建候选，避免整页重写被截断；复用 RGC DockerGame 的隔离引擎与真实截图/视频，未直接声称复现完整上游 Loop 或论文实验。上游版本、许可和资源限制补丁见 `worker/UPSTREAM.txt`。
- 玩家策略是模型生成的**数据型 JSON 按键序列**，不执行模型编写的 Python。每版覆盖初见引导、目标尝试、失败恢复三类目的；每局最多 24 步、每步最多 1 秒。策略按各版学习，路线不保证相同，因此结果不是严格控制变量的人类实验。执行完策略不等于获胜。桥接状态、截图和轨迹共同作为证据；桥接自身的语义诚实性仍需人工审查。
- 评审只接收匿名 A/B 的真实轨迹与标注路径的截图，不提供源码或新旧顺序。只有两次都偏好候选、候选试玩有效、引用路径存在，才保留候选；其余保留旧版。证据文件带哈希清单，读取和导入时校验。
- 模型预算在派发前落盘，usage 实际返回才记录，费用未知保留 null。已完成调用恢复时复用；失去响应的已派发调用不会自动重复计费，而是报 ambiguous，必须显式发起新任务才能重试。停止与预算在模型等待中轮询；远端已收到的请求无法保证撤销收费。
- 预算或停止时交付此前已经验证的最佳结果。未完成试玩不写成完整 receipt；恢复从该阶段重新试玩、复用已完成模型策略。启动失败/心跳过期进入失败状态，允许检查后恢复。

## 安全与部署范围

这是单所有者的本地工具，未实现多租户账户。默认启动绑定回环地址；如自行公开服务，必须设置 `GAMEFORGE_ACCESS_TOKEN`（Bearer 或 HTTP Basic 密码），并配置 HTTPS。不要把裸 `next -H 0.0.0.0` 当作安全的远程部署方式。请求 Host 约束和跨域写入拦截只是辅助防护。

生成 HTML 在无同源权限的 iframe 中预览，CSP 禁止连接、外部脚本、表单和对象。游戏容器网络关闭、文件系统只读、非 root、移除 capabilities、no-new-privileges，并限制 1 GB 内存、2 CPU、256 进程。容器只挂载冻结源、输出和框架，不挂载模型密钥、Docker socket 或其他项目。控制器在可信用户下拥有 Docker 权限，因此主机管理员仍属于信任边界。

新版本与任务需要持久本地磁盘和独立 worker。Vercel 临时磁盘 / KV 远端旧部署不支持自动改进，启动会明确拒绝。原有远端存储配置需要单独迁移成持久 worker 部署。不要把此实现宣称为生产多租户服务。

## 验证入口

- `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build`。
- `python -m unittest discover -s worker -p "test_*.py"`。
- 已有真实游戏离线与字节验证：`node scripts/live-e2e.mjs <gameId...>`；需要 Playwright 浏览器，或设置 `GAMEFORGE_TEST_BROWSER=chrome` 使用本机 Chrome。此命令不触发付费生成。
- 真实执行记录与明确未覆盖项见 [测试报告](TEST_REPORT.md)。

结构化调用使用供应商 JSON mode，并在本地继续验证；协议说明见 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。
